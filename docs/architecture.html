Project structure

The repository separates the browser interface, HTTP API, and reusable filesystem storage layer. JSON records describe workspaces; files and packages live alongside those records.

Repository map

.
├── Backend/                 FastAPI entry point, routes, services, and models
│   ├── main.py              App setup, API registration, frontend serving
│   ├── Routes/              HTTP endpoints under /api
│   ├── Functions/           Route-facing business operations
│   └── Models/              API request and response models
├── Pawm/                    Python filesystem storage API and managers
├── src/                     Vue 3 + TypeScript frontend source
│   ├── Pages/               Home, profile, and workbook screens
│   ├── Comps/               Feature components and dialogs
│   ├── Widgets/              Shared interface controls
│   └── stores/              Frontend API and state stores
├── Frontend/                Built frontend served by FastAPI
├── Storage/                 Data directory configured by the web backend
├── public/                  Static assets, including LOGO.svg
└── docs/                    This static documentation site

The backend registers routers for profiles, workbooks, API keys, callers, tools, sources, chat, and outputs. FastAPI also serves the compiled frontend and exposes a health endpoint.

Local data layout

The web app’s configured storage root is the repository’s Storage/ folder. Each profile has a directory containing its records and workbook content:

Storage/
├── profiles.json
└── Profiles/
    └── <profile-id>/
        ├── api_keys.json
        ├── callers.json
        ├── tools.json
        ├── workbooks.json
        ├── Callers/
        ├── Tools/
        └── Workbooks/
            └── <workbook-id>/
                ├── config.json
                ├── chat.json
                ├── sources.json
                ├── outputs.json
                ├── Sources/
                └── Outputs/

Record files contain metadata; associated content and uploaded package files live in their corresponding directories. Contents can vary as the application adds data.

Storage API versus web app

Pawm/STORAGE.py exposes the Python Storage class, profile and workbook managers, and resource helpers. The storage initializer defaults to Documents/PAWM_DATA when called without a directory. The web backend constructs it with an explicit repository-local Storage/ path, so the web app uses that override.

Keep local storage out of public repositories and shared archives when it contains credentials or private workbook content. Back up important data before changing or removing files.
