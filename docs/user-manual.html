GUIDE 02 · USING PAWM

User manual

PAWM (Personal WorkBook LM) is a local workspace for organizing model-assisted work. Profiles group settings and resources; workbooks give each project a place for conversations, sources, and outputs.

1. Create and manage profiles

Start on the home screen. Choose Create profile, enter a name, and optionally add a description and PNG, JPEG, or WebP thumbnail (up to 1 MB). Select Enter to open a profile. Use Settings to edit its details, or Delete to remove it.

A profile is the top-level workspace boundary. Its workbooks, API keys, callers, and tools are managed within that profile. Deleting a profile removes its associated local data.

2. Create and manage workbooks

Inside a profile, open Workbooks and select Create workbook. A title is required; a description and optional image thumbnail help identify it. Open a workbook to work in its chat and manage workbook resources.

  • Search the workbook list by title or description.
  • Within a workbook, use its resource controls to organize sources and outputs alongside the conversation.
  • Delete only when you intend to remove the workbook and its associated content; deletion cannot be undone from the interface.

3. Add an API key

API keys are configured per profile. Open the profile’s API keys section and choose Add API key. Enter:

  • Name and optional description to recognize the provider or account.
  • Base URL for the API service.
  • At least one endpoint, with a unique name and path, such as chat and /v1/chat/completions.
  • Secret / API key, required when creating an entry.
  • Metadata, an optional valid JSON object for provider-specific settings.

Select Add API key to save. The table shows a key preview, not the full secret. When editing, leave the secret blank to keep the existing value. Use View, Edit, or Delete to manage entries.

Keep credentials private

Credentials are stored by the local application. Do not publish or share your Storage/ directory. The interface does not display a saved full secret.

4. Create a caller

Open a profile’s Callers section and choose Add caller. Give it a unique name and description, then provide Python source that defines both required functions:

def INVOKE(**kwargs):
    return {
        "success": True,
        "model": kwargs.get("model", ""),
        "message": {"role": "assistant", "content": "Your response"},
    }

def MODEL(**kwargs):
    return {"success": True, "models": [{"id": "example-model", "name": "Example Model"}]}

INVOKE receives the selected API key, base URL, endpoint, model, messages, and generation settings as keyword arguments. It must return {"success": true, "message": {"role": "assistant", "content": "..."}}; an optional usage object is saved with the response. MODEL returns a list of models with id and name. Select the caller in the workbook chat’s Model & API menu. The caller is an adapter; add its API credential separately under API keys.

5. Create a tool package

A tool package is a ZIP with these non-empty files at its root:

my_tool.zip
├── main.py       Python functions
├── schema.json   Model-facing function schemas
└── README.md     Package notes

For example, schema.json uses the OpenAI function-tool format:

[
  {
    "type": "function",
    "function": {
      "name": "echo_text",
      "description": "Return the supplied text.",
      "parameters": {
        "type": "object",
        "properties": {"text": {"type": "string"}},
        "required": ["text"]
      }
    }
  }
]

Then define a matching function in main.py:

def echo_text(text: str) -> dict[str, str]:
    return {"text": text}

Open a profile’s Tools section, choose Upload tool ZIP, enter a title and optional description, then upload the archive. ZIP uploads are limited to 10 MB. Select the tool in a workbook’s Settings tab to enable it; PAWM’s built-in tools are selected by default for newly created workbooks. Edit to replace a package or update its details; Delete removes it from the profile.

Run trusted code only

Tool functions execute as Python code on the machine running PAWM. The built-in Python and shell runners use temporary working directories and timeouts, but are not operating-system security sandboxes.

6. Callers, sources, and outputs

Callers represent model integrations available to a profile. API key credentials are configured separately; selecting or configuring a caller does not itself add an API secret.

Sources are materials associated with a workbook, such as local files or links. Outputs are files or content produced and kept with that workbook. Use the workbook’s side panels to manage resources and preview supported content.

7. Built-in defaults

When a workbook is created, PAWM copies any missing built-in callers and tools into the profile and stores their IDs in the workbook configuration. Builtin manifest path values are made absolute on first import; a relative_path fallback keeps packages relocatable across checkouts. The default caller is preselected in chat. An API key is never created automatically; add one to the profile and select it in workbook settings before sending a message.

8. Troubleshooting

  • If the app does not load, confirm the backend is running at port 8080 and the Frontend/ bundle exists.
  • If a profile or resource cannot be found, confirm you are in the correct profile and check the local data folder.
  • For API errors, open http://localhost:8080/docs to inspect backend endpoints.
